# i18n — Perfumes Dubai

Trilingual setup with `next-intl@4` and the App Router `[locale]` segment.

## Locales

| Code | Display    | URL prefix | Direction |
| ---- | ---------- | ---------- | --------- |
| `es` | Español    | none (`/`) | LTR       |
| `en` | English    | `/en`      | LTR       |
| `ar` | العربية    | `/ar`      | **RTL**   |

`es` is the default — `localePrefix: "as-needed"` in `i18n/routing.ts` means the default locale never carries a URL prefix.

## Source of truth

```
i18n/
  routing.ts        ← locales, defaultLocale, prefix strategy
  navigation.ts     ← typed Link, useRouter, usePathname
  request.ts        ← per-request config: loads messages/${locale}.json
middleware.ts       ← createMiddleware(routing) — locale detection
messages/
  es.json           ← canonical strings (brand voice in Spanish)
  en.json           ← English adaptation (cultural, not literal)
  ar.json           ← Arabic adaptation (cultural, RTL-safe)
```

`next.config.ts` wraps the export in `withNextIntl("./i18n/request.ts")` so the plugin can wire request resolution.

## Adding a namespace

1. Edit each `messages/*.json` and add the namespace at the top level:

   ```json
   {
     "product": {
       "details_title": "Détails",
       "price_label": "Prix"
     }
   }
   ```

   Keep all three files in lock-step. Missing keys throw at runtime.

2. Read the strings — pick the right API for the runtime:

   **Server Components / Server Actions** (preferred, async):

   ```ts
   import { getTranslations } from "next-intl/server";
   const t = await getTranslations("product");
   t("details_title");
   ```

   **Client Components** (only when truly needed):

   ```tsx
   "use client";
   import { useTranslations } from "next-intl";
   const t = useTranslations("product");
   ```

3. For Server Components inside `[locale]/`, always call
   `setRequestLocale(locale)` at the top of the page so `next-intl` can
   render statically. Already done in `layout.tsx`, `page.tsx`, and
   `styleguide/page.tsx` — copy the pattern when you add new pages.

## Server vs Client

- `getTranslations(namespace)` — async, RSC-only, no provider needed.
- `useTranslations(namespace)` — sync hook, requires `NextIntlClientProvider`
  in the tree (already wired in `app/[locale]/layout.tsx`).
- Both consume the same `messages` object resolved by `i18n/request.ts`.

## Arabic copy — rules (see brief §8)

- **Never translate literally.** Adapt the metaphor so it lands in
  cultural register. Where possible, reuse the approved phrases from
  brief §13 verbatim.
- The `<html>` element receives `dir="rtl" lang="ar"` automatically when
  the active locale is `ar` (see `app/[locale]/layout.tsx`).
- The body switches font stack to `font-arabic` (IBM Plex Sans Arabic
  for UI, Noto Naskh Arabic for display) via the same layout.
- Punctuation, numerals, and arrows must use Arabic-appropriate forms
  (`←` for "forward" in copy, Arabic-Indic digits where typographically
  better).
- Components that mirror visually (chevrons, sliders) should rely on
  `[dir="rtl"]` CSS selectors in `app/globals.css` rather than ad-hoc
  flipping in TSX.

## Locale switching at runtime

`components/layout/LocaleSwitcher.tsx` exposes a minimal client widget
that uses `useRouter` + `usePathname` from `@/i18n/navigation` so the
current pathname is preserved while the locale prefix is rewritten.
Render it inside any layout — it picks up the active locale via
`useLocale()`.

## Adding a new locale

1. Add the code to `routing.locales` in `i18n/routing.ts` (the tuple is
   `as const`, so TypeScript will instantly surface any place that
   doesn't account for it).
2. Create `messages/<new>.json` mirroring the existing shape.
3. If RTL, extend the `isRtl` check in `app/[locale]/layout.tsx`:

   ```ts
   const RTL_LOCALES = new Set(["ar", "he", "fa"] as const);
   const isRtl = RTL_LOCALES.has(locale as never);
   ```

4. Add the human label to the `locale_switcher` namespace in every
   `messages/*.json` so the switcher menu renders the new option.
5. Rebuild — `generateStaticParams` automatically derives params from
   `routing.locales`.
